# oramacore-cpp v0.1.0

The first release of oramacore-cpp, a C++23 rewrite of the [OramaCore](https://github.com/oramasearch/oramacore)
search engine. It is a library: link it in and index and search documents in your own process. This
release provides BM25F full-text search over an in-memory index.

## What it includes

Everything in the public headers under `include/oramacore/`:

- **BM25F scoring** (`bm25f.hpp`)
  - `FieldParams` (a field's weight and length normalization `b`) and `Params` (the global `k1`). The
    defaults match OramaCore: weight 1.0, `b` 0.75.
  - `idf()`, `pseudo_tf()` (per-field contributions summed before saturation, as BM25F defines it),
    `score_term()` and `score()`.
- **Tokenization** (`tokenize.hpp`)
  - `tokenize()` with `Options`: lowercasing, English stop words, a minimal suffix stemmer, and a minimum
    token length. Each token records where it came from in the source text.
  - `normalize()`, `is_stop_word()` and `stem()`.
- **The in-memory index** (`index.hpp`, `MemoryIndex`)
  - **Fields:** declare fields with their own BM25F parameters; any other field a document carries is
    registered on first sight with the defaults.
  - **`add()`** indexes a document and returns its `DocId`, as a `Result<DocId>`. Its cost is in proportion to
    the document's own fields.
  - **`search(query, top_k)`** scores multi-term queries: per-term scores are summed per document, and the
    hits come back sorted.
  - **Sharded search:** `stats(query)` returns a shard's `CorpusStats`; `CorpusStats::merge()` combines
    shards; `search(query, top_k, global)` scores one shard with the merged statistics, so the results
    match a single index over the whole corpus.
  - **`Limits`:** at most 1,000,000 fields, 1,000,000 per document, and 1,024-byte field names by default,
    all configurable. A document over a limit is refused, and the index is left unchanged.
- **Errors** (`error.hpp`): `Result<T>` is `std::expected<T, Error>`; no exception crosses the public API.
- **Version** (`version.hpp`): `kName` and `kVersion`.
- **CMake target** `orama::oramacore-cpp` (a static library).
- **Benchmarks** (`bench/`): `oramacore-cpp-bench` (`-DORAMACORE_CPP_BENCH=ON`) profiles index build and
  search over a CSV. `bench/rust-comparison/` drives OramaCore's own index over the same data and
  protocol. The results and their caveats are in [`bench/README.md`](../../bench/README.md).
- **License files:** MIT (`LICENSE`, `COPYRIGHT`), `THIRD_PARTY_LICENSES`, an SBOM (`sbom.spdx.json`,
  `sbom.cdx.json`, made by `tools/sbom.py`), `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md` and `SECURITY.md`.

## What it does not include

- **Persistence:** the index lives in memory only, and nothing is saved or reloaded (#1).
- **Changing documents:** documents can be added but not deleted or updated.
- **Other index types:** prefix, geo, filters and vector search are planned.
- **Asynchronous search:** coroutine-based search on Boost.Capy is planned (`-DORAMACORE_CPP_CAPY`).
  Today everything is synchronous.
- **Other languages:** the tokenizer handles English only.
- **A score-parity check** against OramaCore on shared fixtures is not written yet.

## Known issues

- **Security:** none open.
- **Breaking change for programs that pinned an earlier commit:** `MemoryIndex::add()` returns
  `Result<DocId>` instead of `DocId`, and must be checked.
- **The benchmark links AGPL crates:** the separate benchmark program `bench/rust-comparison` links
  OramaCore's Rust crates, which are AGPL-3.0 today. The library itself has no third-party code.
